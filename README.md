# librosa-rs

[![CI](https://github.com/DaniilPak/librosa-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/DaniilPak/librosa-rs/actions/workflows/ci.yml)
[![crates.io](https://img.shields.io/crates/v/librosa-rs.svg)](https://crates.io/crates/librosa-rs)
[![docs.rs](https://docs.rs/librosa-rs/badge.svg)](https://docs.rs/librosa-rs)

Pure-Rust audio and music analysis that returns the same numbers as Python's
[librosa](https://github.com/librosa/librosa). It covers STFT, mel spectrograms, MFCC,
chroma, CQT/VQT, spectral features, onset detection, tempo and beat tracking, YIN/pYIN, HPSS,
time-stretching and pitch-shifting, all checked against librosa 1.0 reference outputs.

> **This is an independent project. It is not affiliated with or endorsed by the librosa
> developers.** It follows librosa's algorithms, defaults and module layout so results can be
> compared one to one. Credit for the methods and their reference implementation goes to the
> librosa team (ISC license, see [Credits](#credits)).

- No Python, no C dependencies: decoding by [`symphonia`](https://crates.io/crates/symphonia),
  FFTs by [`realfft`](https://crates.io/crates/realfft) / [`rustfft`](https://crates.io/crates/rustfft),
  arrays by [`ndarray`](https://crates.io/crates/ndarray).
- Computes in `f64` throughout.
- Tested against fixtures generated by real librosa 1.0.0 (numpy 2.5, scipy 1.18).

## Install

```toml
[dependencies]
librosa-rs = "0.1"
```

The library is imported as `librosa`:

```rust
use librosa::feature::{mfcc, MfccParams};
```

## Example

```rust,no_run
use librosa::beat::{beat_track, BeatTrackParams};
use librosa::feature::{chroma_stft, melspectrogram, mfcc, ChromaStftParams, MelSpectrogramParams, MfccParams};
use librosa::{frames_to_time, load, pyin, stft, LoadOptions, PyinParams, StftParams};

fn main() -> librosa::Result<()> {
    // librosa.load(path)  -> mono, resampled to 22050 Hz
    let (y, sr) = load("song.mp3", &LoadOptions::default())?;

    // librosa.stft(y)
    let d = stft(y.view(), &StftParams::default())?; // (1025, n_frames) complex

    // librosa.feature.melspectrogram(y=y, sr=sr) and mfcc(y=y, sr=sr, n_mfcc=13)
    let mel = melspectrogram(&y, sr, &MelSpectrogramParams::default())?;
    let mfccs = mfcc(&y, sr, &MfccParams { n_mfcc: 13, ..Default::default() })?;

    // librosa.feature.chroma_stft(S=np.abs(D)**2) — pass a spectrogram instead of audio
    let power = d.mapv(|z| z.norm_sqr());
    let chroma = chroma_stft(&power, sr, &ChromaStftParams::default())?;

    // librosa.beat.beat_track(y=y, sr=sr)
    let (tempo, beats) = beat_track(y.view(), sr, &BeatTrackParams::default())?;
    let frames: Vec<i64> = beats.iter().map(|&b| b as i64).collect();
    println!("{tempo:.1} BPM, beats at {:?} s", frames_to_time(&frames, sr, 512, None));

    // librosa.pyin(y, fmin=65, fmax=2093, sr=sr)
    let f0 = pyin(y.view(), 65.0, 2093.0, sr, &PyinParams::default())?;
    println!("{} frames, {} voiced", f0.f0.len(), f0.voiced_flag.iter().filter(|v| **v).count());
    let _ = (mel, mfccs, chroma);
    Ok(())
}
```

Run the bundled example on any file: `cargo run --release --example analyze -- file.wav`.

### How the API maps to librosa

- Keyword arguments become a `...Params` struct whose `Default` holds librosa's defaults, so
  `librosa.stft(y, n_fft=1024, center=False)` is
  `stft(y.view(), &StftParams { n_fft: 1024, center: false, ..Default::default() })`.
- Functions that take either `y=` or `S=` take `impl Into<feature::Input>`. Pass `&Array1<f64>`
  for audio or `&Array2<f64>` for a spectrogram.
- `ref=np.max` is `DbRef::Max`, `norm=np.inf` is `Some(Norm::Inf)`, `res_type="fft"` is `ResType::Fft`.
- Signals are mono `Array1<f64>`. Use `load_multichannel` / `to_mono` for multichannel files.
  Frame-indexed outputs are `(features, frames)` matrices, as in librosa.

### Notes on the remaining differences

- **Resampling.** librosa's default resampler is soxr (C). The default here (`ResType::Sinc`) is a
  zero-phase Kaiser-windowed sinc with 64 zero crossings, computed with exact per-phase
  filters for rational rate ratios. It agrees with soxr to about 130 dB on band-limited
  signals; only content in the last ~3% below Nyquist differs. For exact agreement, use
  `ResType::Fft` or `ResType::Polyphase`, which match librosa's `res_type="fft"` /
  `"polyphase"` exactly. The optional `rubato` feature adds `ResType::Rubato` (rubato's
  streaming sinc resampler). It is faster on long inputs, but rubato trims its startup delay
  in whole samples, which leaves a sub-sample offset relative to librosa.
- **float32 defaults in librosa.** Some librosa defaults store intermediates as float32: the
  mel/chroma filter banks (`dtype=np.float32`), `rms` (`dtype=np.float32`) and the CQT wavelet
  basis (complex64). librosa-rs stays in float64, so it matches librosa called with
  `dtype=np.float64` to ~1e-9. Against the float32 defaults the agreement is ~1e-5 relative.
- **Lossy decoders.** MP3/Vorbis decoding uses symphonia instead of libsndfile/mpg123. Decoders
  may differ in the last bits and in MP3 priming/padding.

## Testing

```bash
cargo test
```

The fixtures were generated with `tests/gen/generate.py` (librosa 1.0.0) from synthetic
signals: sine, chirp, white noise, a C-major chord, a 120-BPM click track, a vibrato
"voice" and a gapped tone. All are produced by the script and released as CC0. To regenerate:

```bash
python -m venv .venv && .venv/bin/pip install librosa soundfile
.venv/bin/python tests/gen/generate.py
```
